# In-app updates / Nazzelha 0.5.3

The repository and GitHub Releases are public. No token, account or backend is needed in the Android app. Settings → App updates → Check for updates queries the public latest stable release and downloads the APK and manifest from verified GitHub release URLs. Automatic checks can be enabled and run at most daily when opening the app. Android asks the user to confirm installation.

One-time signing setup: run ci/setup-update-signing.sh on a trusted computer with Java, OpenSSL and authenticated gh. Back up the key privately. Never replace it or commit it. CI publishes a public GitHub Release with Nazzelha-arm64.apk and update.json only when persistent signing, signature checks and both emulator smoke tests succeed. Without the signing secrets, CI only produces debug test artifacts. Existing ephemeral-debug APKs cannot update to the new signing key; a one-time uninstall and install of the first signed release is necessary (app-private data may be lost). Keep versionCode increasing for future releases.

Before handing the downloaded APK to the Android installer, the app checks package, strictly newer version, size, SHA-256, matching signing certificates and trusted HTTPS download hosts. Existing private update credentials are removed. CI smoke tests include checking the public release endpoint and confirming that there is no newer published version. End-to-end upgrade between two signed releases still requires a persistent signing key and two tested release versions.
