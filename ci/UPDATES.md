# In-app updates / Nazzelha 0.5.5

The repository and GitHub Releases are public. No token, account or backend is needed in the Android app. Settings → App updates → Check for updates downloads the public latest release manifest directly (without the anonymous REST API rate limit), then uses its version-specific APK URL. Automatic checks can be enabled and run at most daily when opening the app. Android asks the user to confirm installation.

One-time signing setup: run ci/setup-update-signing.sh on a trusted computer with Java, OpenSSL and authenticated gh. Back up the key privately. Never replace it or commit it. CI publishes a public GitHub Release with Nazzelha-arm64.apk and update.json only when persistent signing, signature checks and both emulator smoke tests succeed. Without the signing secrets, CI only produces debug test artifacts. Existing ephemeral-debug APKs cannot update to the new signing key; a one-time uninstall and install of the first signed release is necessary (app-private data may be lost). CI also records the certificate fingerprint and rejects a release if its signer differs from the previous published version or its versionCode does not increase. Keep versionCode increasing for future releases.

Before handing the downloaded APK to the Android installer, the app checks package, strictly newer version, size, SHA-256, matching signing certificates and trusted HTTPS download hosts. Existing private update credentials are removed. CI smoke tests include checking the public release endpoint and confirming that there is no newer published version. End-to-end upgrade between two signed releases still requires a persistent signing key and two tested release versions.

## Engine updates
Settings → Update yt-dlp displays the real installed version and offers Update now. The updater runs yt-dlp's own CLI `--update-to stable` (the stable-channel equivalent of `-U`) through the embedded Python runtime. Upstream handles release lookup, compatibility rules, download and checksum validation. The app keeps a backup, rejects missing-hash/verification warnings, reads `--version` after the command, and restores the previous binary if the update fails. No custom release downloader or ZIP parser is used. It serializes replacement against active engine commands. On a classified extractor/version failure, the app checks for an update and retries the same operation once only when a newer engine is installed (or another worker already updated it). Generic network, access, storage, format and cancellation errors do not trigger updates. Automatic checks after failures have a five-minute cooldown. Original and retry errors are preserved. CI includes recovery-policy unit tests and separate native engine update smoke tests; real live YouTube transfers are not implied by these tests.

## ABI-correct CI checks
The distributed APK remains ARM64. Its exact signed file must install and pass UI smoke tests in the standard and 16 KB Android 15 images. An additional APK built from identical sources with the x86_64 native libraries is exclusively a CI test artifact: it must execute yt-dlp, perform the real stable engine update check/install, and read the installed version again. This avoids ARM-to-x86 native-bridge linker failures. All three jobs must pass before publishing the ARM64 release. This does not establish a successful live YouTube transfer or native ARM64 engine execution on a real device.

## Differential APK updates
Starting with v0.5.5, the app chooses a small signed-APK delta if the installed base APK's version, byte size and SHA-256 exactly match a manifest entry. CI creates bounded NZD1 copy/literal patches from up to three prior public signed releases, verifies the reconstructed file's SHA-256 and signature, and runs the same Kotlin parser used on Android against the real APKs. Native runtime files (lib/) are fingerprinted; if they change or a delta is at least 70% of the full APK, no delta is published for that base. If the installed APK was repacked, is split, is too old, or no usable delta exists, the UI offers the full APK. If a chosen delta fails, the user must explicitly approve the full download. Android still installs the entire reconstructed signed APK locally using the original package identity and certificate; only the network transfer is smaller. v0.5.4 and earlier need one full update to gain delta support. The yt-dlp self-update stays separate. No additional runtime dependency is used.

## Ink & Coral identity
Native Android UI refresh retains the existing language, workflow and palette, with vector icons, rounded controls/cards, themed dialogs, compact settings, and generic engine labels. A per-job progress model uses explicit yt-dlp stream progress records and estimated byte weights for video/audio, holds the same progress through merge and save, and reserves 100% for successful MediaStore publication. Unknown sizes use equal stream weights; stream ETA is withheld until other streams have completed. Unit tests exercise combined, two-stream, unknown-size and ETA behavior. The approved concept is a direction, not a promise of pixel-identical screens or new premium, storage, browser or pause features.
