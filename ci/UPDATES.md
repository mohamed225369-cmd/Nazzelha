# In-app updates / Nazzelha 0.5.4

The repository and GitHub Releases are public. No token, account or backend is needed in the Android app. Settings → App updates → Check for updates downloads the public latest release manifest directly (without the anonymous REST API rate limit), then uses its version-specific APK URL. Automatic checks can be enabled and run at most daily when opening the app. Android asks the user to confirm installation.

One-time signing setup: run ci/setup-update-signing.sh on a trusted computer with Java, OpenSSL and authenticated gh. Back up the key privately. Never replace it or commit it. CI publishes a public GitHub Release with Nazzelha-arm64.apk and update.json only when persistent signing, signature checks and both emulator smoke tests succeed. Without the signing secrets, CI only produces debug test artifacts. Existing ephemeral-debug APKs cannot update to the new signing key; a one-time uninstall and install of the first signed release is necessary (app-private data may be lost). CI also records the certificate fingerprint and rejects a release if its signer differs from the previous published version or its versionCode does not increase. Keep versionCode increasing for future releases.

Before handing the downloaded APK to the Android installer, the app checks package, strictly newer version, size, SHA-256, matching signing certificates and trusted HTTPS download hosts. Existing private update credentials are removed. CI smoke tests include checking the public release endpoint and confirming that there is no newer published version. End-to-end upgrade between two signed releases still requires a persistent signing key and two tested release versions.

## Engine updates
Settings → Update yt-dlp displays the real installed version and offers Update now. The updater uses the official stable zipapp and SHA2-256SUMS over HTTPS, validates the ZIP and executes --version, and restores the previous binary if validation fails. It serializes replacement against active engine commands. On a classified extractor/version failure, the app checks for an update and retries the same operation once only when a newer engine is installed (or another worker already updated it). Generic network, access, storage, format and cancellation errors do not trigger updates. Automatic checks after failures have a five-minute cooldown. Original and retry errors are preserved. CI includes recovery-policy unit tests and engine-version UI smoke tests; real live YouTube transfers and the network update itself are not implied by these tests.
